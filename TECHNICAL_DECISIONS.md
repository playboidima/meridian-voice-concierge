# Ключові технічні рішення Core

## Архітектура

```text
LiveKit Agents Playground
          |
          v
LiveKit Cloud <-> Python voice agent (STT -> LLM -> TTS)
                           |
                           v
                     FastAPI Backend
                       |         |
                       v         v
                  FAQ search   unanswered aggregation
                       \         /
                        PostgreSQL + pgvector
```

Проєкт навмисно залишається простим монорепозиторієм із трьома Docker Compose
сервісами: `agent`, `backend` і `db`. Окремі шари або брокери повідомлень не
додані, оскільки вони не потрібні для Core і ускладнили б локальний запуск.

## Backend і база даних

- FastAPI надає три стабільні маршрути: `GET /health`,
  `POST /api/faq/search` і `POST /api/unanswered`.
- PostgreSQL зберігає FAQ та невідповідані питання. Alembic створює схему й
  розширення `pgvector` під час запуску Backend.
- Seed виконується після міграцій і є повторно безпечним: FAQ оновлюються за
  унікальним `question`, а дублікати не створюються.
- `UnansweredQuestion.frequency` збільшується одним PostgreSQL
  `INSERT ... ON CONFLICT DO UPDATE`. Це не втрачає збільшення, коли однакове
  питання надходить одночасно з кількох сесій.

## Пошук FAQ

Пошук гібридний:

1. Lexical scoring дає пріоритет сильним точним збігам і перевіреним aliases.
2. Semantic retrieval використовує локальну модель
   `BAAI/bge-small-en-v1.5` через FastEmbed.
3. Вектори розмірності 384 зберігаються в PostgreSQL; пошук виконується за
   cosine similarity через HNSW-індекс pgvector.
4. Якщо надійного збігу немає, API повертає `matched: false`, а не найближчу
   випадкову відповідь.

Пороги винесені в env: загальний `FAQ_MATCH_THRESHOLD=0.35`, semantic
`SEMANTIC_MATCH_THRESHOLD=0.65`. Сильний lexical match має внутрішній поріг
`0.45`. Значення відкалібровані на відомих сценаріях PRD, природних англійських
перефразуваннях і негативному наборі невідомих питань.

## Голосовий агент

- LiveKit Agents на Python забезпечує кімнату, STT, LLM, TTS, turn detection і
  можливість перебивання мовлення.
- Для Core використовується LiveKit Inference, тому окремі ключі STT/LLM/TTS
  не потрібні. Конкретні моделі та голос задаються через env без редагування коду.
- Агент працює лише англійською. Оригінальне питання гостя передається до
  Backend без перекладу або перефразування.
- Для кожного фактичного питання агент викликає один інструмент. Він спочатку
  шукає FAQ і автоматично записує unknown лише при `matched: false`.
- Prompt забороняє вигадувати факти. Якщо Backend або запис недоступні, агент
  радить підтвердити інформацію у персоналу й не заявляє, що питання записано.

Для браузерного тестування використовується LiveKit Agents Playground. Він
надає мікрофон, аудіовихід, індикатори стану та Start/End без розробки окремого
гостьового сайту, що прямо дозволено PRD.

## Секрети та локальний запуск

- `.env` виключений із Git; репозиторій містить лише `.env.example` без ключів.
- Увесь Core запускається командою `docker compose up --build`.
- Health-check-и контролюють PostgreSQL, Backend і процес агента.
- Міграції, seed і локальна embedding-модель включені в Docker workflow.

## Компроміси та межі Core

- Англійські semantic passages підтримуються поруч з українськими seed-даними.
  Це дозволяє англомовному агенту шукати без LLM-перекладу, але після значного
  розширення FAQ пороги потрібно повторно відкалібрувати.
- Нормалізація агрегує однакові формулювання unknown-питань; семантично близькі,
  але текстово різні формулювання можуть залишитися окремими записами.
- LiveKit Playground, Cloud та Inference потребують інтернету і дійсних
  credentials користувача.
- Бронювання, платежі, авторизація, React-адмінпанель, CRUD FAQ та керування
  чотирма голосами належать до Bonus або поза межами завдання й не реалізовані.
